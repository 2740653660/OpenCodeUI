# 发布流程（个人安装包）

> 本文件是"怎么给使用者出安装包"的操作手册，只存在于 fork 的个人区（`idea/`），**绝不允许进入发往上游的 PR**。

## 什么时候发布

- 需求完成后，问使用者："现在出安装包吗？"，**使用者同意才发**；
- 使用者也可以随时主动说"帮我发布"；
- **铁律：未经使用者确认，绝不擅自发布。**

## 发布前的前置条件（必须全部满足）

1. 本次要发布的功能代码已合并回本地 `main` 并推送到 `origin`（发布从远端 `main` 构建）；
2. 确认打包脚本 `.github/workflows/release.yml` 存在且包含 `workflow_dispatch` 入口（本 fork 上"推标签自动触发"不生效，只能手动触发，此入口已配置好）。

## 发布步骤

1. 检查前置条件：`git status` / `git log origin/main -1`，确认本地与远端 `main` 同步。
2. 起版本号：格式 `v0.6.35-pN`（N 从 1 递增：p1、p2、p3……）。
   已发过哪些版本见：https://github.com/2740653660/OpenCodeUI/releases
3. 执行发布（AI 操作，使用者无需动手）：

   ```bash
   gh workflow run release.yml -R 2740653660/OpenCodeUI -f version=v0.6.35-pN
   ```

4. 等待打包完成（15~30 分钟，第一次较慢）。观察进度：

   ```bash
   gh run watch -R 2740653660/OpenCodeUI --exit-status --interval 30
   ```

   失败时看日志排查：`gh run view --log-failed -R 2740653660/OpenCodeUI`
5. 打包成功后，安装包出现在发布页：https://github.com/2740653660/OpenCodeUI/releases
   - **Windows**：`OpenCode_0.6.35_x64-setup.exe`（双击覆盖安装，本地设置保留）
   - **手机**：`OpenCodeUI-v...-android-arm64.apk`（近两年手机都是 arm64）

## 安装注意事项（务必告诉使用者）

- 手机**第一次**装"个人版"APK，必须先**卸载官方版**再安装（签名印章不同，安卓不允许覆盖安装）；
  模型配置在 OpenCode 后端，卸载不损失任何东西；装完重新打开、重新填一下后端地址即可。
- 以后每次再装"个人版"APK，都可以直接覆盖升级（印章一致）。
- Windows 端没有签名限制，直接覆盖安装即可。

## 重要备份（签名印章）

- 安卓 APK 的签名印章文件位于：`~/.local/share/opencodeui-android/`（`keystore.jks` + `KEY-INFO.txt`）。
- GitHub 仓库里的密钥（`ANDROID_KEY_*`）**无法再读出来**，本地这两个文件是唯一可恢复的备份。
- 每次发布后（或定期）提醒使用者把这两个文件备份到网盘 / 移动硬盘。
- **印章丢失的后果**：以后每次手机升级都要先卸载重装（换了新印章，签名就不一致了）。

## 残余风险

- 上游若修改 `release.yml`，合并到本地 `main` 时可能冲突，需人工处理（AI 处理）。
- 手动触发的发布页上更新说明会是"没有找到更新记录"，不影响安装包本身。
