# 在设置页一键管理 AI 供应商和模型

- 创建日期：2026-08-02
- 优先级：高

## 背景 / 痛点

目前添加或修改 AI 供应商，需要手动编辑复杂的 OpenCode 配置。对于不了解配置文件的用户来说，不清楚供应商 ID、接口类型、API 地址、模型 ID 等字段应该如何填写，也不容易判断配置是否成功。

现有“模型”设置页主要负责隐藏或显示模型，不能完成供应商添加、API Key 保存、模型获取和连接测试。用户需要在多个地方手动配置，操作复杂且容易出错。

## 期望效果

在设置中增加独立的“供应商”管理页面，让用户可以用表单完成供应商和模型配置，不需要直接编辑配置文件。

### 官方供应商

- 从当前 OpenCode 后端动态读取官方供应商列表。
- 用户选择供应商并填写 API Key。
- API Key 保存到 OpenCode 配置中的 `provider.<供应商ID>.options.apiKey`。
- 不要求用户手动填写复杂的 npm 包、接口协议等高级配置。

### 自定义供应商

支持以下三种接口协议：

- OpenAI Chat Completions，通常使用 `/v1/chat/completions`。
- OpenAI Responses，通常使用 `/v1/responses`。
- Anthropic Messages，通常使用 `/v1/messages`。

用户可以填写：

- 供应商名称或 ID。
- 接口协议。
- API 地址。
- API Key。
- 模型 ID 和显示名称。

API Key 同样保存到 OpenCode 配置中的 `provider.<供应商ID>.options.apiKey`。

### 模型管理

- 根据供应商接口自动获取模型列表。
- 获取成功后由用户勾选需要启用的模型，不默认全部加入。
- 支持刷新模型列表。
- 如果供应商不支持模型列表接口，或者自动获取失败，允许用户手动填写模型 ID。
- 模型保存后出现在现有模型选择器中。
- 现有“设置 → 模型”页面继续只负责模型的隐藏和显示，不承担供应商添加功能。

### 连接测试

提供“测试连接”按钮：

- 创建一个临时会话。
- 使用用户选择的供应商和模型发送“只回复 OK，不要回复任何其他内容。”。
- 等待模型完成响应。
- 返回内容经过首尾空格处理后，如果等于 `OK`，显示连接成功。
- 认证失败、地址错误、模型不存在、请求超时等情况显示具体错误原因。
- 如果模型有响应但没有按要求返回 `OK`，显示“模型已响应，但没有按要求返回 OK”，并展示实际响应的截断内容。
- 测试完成后删除临时会话，不污染正常会话列表。

### 供应商停用

- 供应商只提供“停用”功能，不提供删除功能。
- 停用时保留原有供应商配置和 API Key。
- 使用 OpenCode 支持的供应商停用配置控制其是否可用。
- 页面中能够区分已启用和已停用的供应商，并支持重新启用。

### 网页端和桌面端

- 网页端先正常显示和尝试“获取模型”功能，不预先禁用。
- 实际测试网页端获取模型是否会受到浏览器跨域限制。
- 如果确认网页端确实无法可靠获取模型，再根据测试结果限制网页端的该功能。
- 桌面端和网页端都应支持供应商配置、保存和连接测试。

### 高级配置

- 保留现有“设置 → 配置 → 渠道与模型”高级配置编辑器。
- 普通用户优先使用新的供应商管理页面。
- 高级用户仍可以通过配置编辑器查看和修改完整的 OpenCode 配置。

## 验收标准

1. 打开设置后，可以看到独立的“供应商”管理入口。
2. 可以从当前 OpenCode 后端加载官方供应商列表。
3. 选择官方供应商并填写 API Key 后，配置能够保存，并且刷新页面后仍然存在。
4. 可以创建自定义供应商，并选择 OpenAI Chat、OpenAI Responses 或 Anthropic Messages 协议。
5. 自定义供应商的 API 地址、API Key 和模型信息可以保存。
6. 支持自动获取模型列表，获取结果可以逐个勾选。
7. 自动获取失败时，页面显示失败原因，并允许手动填写模型 ID。
8. 保存后的模型能够出现在聊天模型选择器中。
9. 可以测试供应商连接，并正确显示成功、失败、超时、认证错误和非 `OK` 响应等结果。
10. 连接测试结束后，临时测试会话会被删除，正常会话列表不出现测试会话。
11. 可以停用和重新启用供应商，停用不会删除已有配置。
12. 现有“设置 → 模型”页面仍然可以正常隐藏和显示模型。
13. 现有“设置 → 配置”高级编辑器仍然可以正常使用。
14. 中文和英文界面都提供对应文案。
15. 通过项目要求的类型检查、代码检查、单元测试和生产构建验证。
